# LeetCode 239. Sliding Window Maximum (v2 新手極速秒懂版)
來源文件：d:\@高通面試\leetcode\239_Sliding_Window_Maximum.html

## 核心一句話
Sliding Window Maximum — 比你晚進來還比你大，前面直接淘汰：用單調雙端佇列一次掃完視窗最大值。
白話核心只有一句：窗框每往右滑一格，名單只留「還沒出框」且「未來還有機會當最大」的人。新來的如果比隊尾大，隊尾永遠沒機會了直接踢掉；如此隊頭永遠就是最大值！

## 60 秒懶人包 (TL;DR)
4 個關鍵符號：
- i：目前走到第幾格（剛進框的新人位置）
- i - k + 1：框框最左邊（小於這格＝掉出框外！）
- dq：候補名單（存位置 idx，由大到小排列：左大 ➔ 右小）
- nums[dq.front()]：名單頭的值（現在這框最大值 👑）

3 步口訣：
- STEP 1 · 頭出框就踢：排第一的人滑出框了嗎？若隊頭位置 < i - k + 1，代表已離開視窗，從頭踢掉：dq.pop_front()
- STEP 2 · 尾比我小就踢：隊尾 <= 新來的，留著也沒用。比新來的弱又早出框，重複從尾踢掉，再把 i 放進隊尾：nums[dq.back()] <= nums[i] ➔ pop_back()
- STEP 3 · 隊頭就是答案：框滿 k 格起，從 i >= k - 1 開始，每一格都記下隊頭對應的數值：res.push_back(nums[dq.front()])

## 00 題意釐清與暴力法為何 TLE
- 長度 n 的陣列、視窗大小 k，總共會產生 n - k + 1 個視窗，每個視窗算 1 個最大值。
- 在 i = 0, 1, ..., k - 2 時，視窗還沒塞滿 k 個元素，不紀錄答案。
- 從 i = k - 1 開始（剛好湊滿第一個視窗 nums[0..k-1]），每往右滑一格就產出 1 個最大值，直到 i = n - 1。
- English Official Spec: You are given an array of integers nums, there is a sliding window of size k which is moving from the very left of the array to the very right. You can only see the k numbers in the window. Each time the sliding window moves right by one position. Return the max sliding window.
- Constraints:
  - 1 <= nums.length <= 10^5（長度最高 10 萬，O(nk) 必超時！）
  - -10^4 <= nums[i] <= 10^4（元素可為負數，初始值別亂設 0）
  - 1 <= k <= nums.length
- 為什麼暴力掃描會 TLE？當 n = 10^5, k = 5 × 10^4，每個視窗重找最大值要 5 × 10^9 次運算，直接超時。
- Deque 裡存「索引」不存值：因為要判斷隊頭是否滑出視窗左界 i - k + 1，存 index 才能同時知道位置與數值 nums[idx]。
- 視窗左界公式 = i - k + 1。
- 均攤 O(1) ➔ 總時間 O(n)：每個索引最多進佇列 1 次、出佇列 1 次，總操作次數 <= 2n。

## 01 硬核術語白話翻譯機（3 大互動實驗）
### Lab 1 · 符號剝洋蔥
- dq 裡面存的是「位置編號 (idx)」，外麵包一層 nums[...] 才是「那個位置的數值」。
- 例：nums = [1, 3, -1, -3, 5]，dq = [1, 2]。
  - dq.back() = 2（只是位置編號 idx = 2）
  - nums[dq.back()] = nums[2] = -1（拿它跟新來的比大小）
  - nums[dq.front()] = nums[1] = 3（目前框內最大值 👑）
- 為什麼不直接存值？反例 nums = [5, 1, 5], k = 2：
  - 視窗滑到 [1, 5] (idx 1..2) 時，如果只存數值 5，根本分不出隊頭的 5 是已經掉出框外的 idx=0，還是剛進來框內的 idx=2！所以一定要存「位置」。

### Lab 2 · 什麼時候「要踢掉」？什麼時候「要留著」？
- 劇本 A（新人 >= 隊尾，必踢）：原本隊伍 [3, -1]，新來了更大的 5。5 比 -1、3 都大，又比他們晚滑出視窗！只要 5 還在框裡，前面較小的永遠不可能當最大值 ➔ 直接從隊尾踢光！
- 劇本 B（新人 < 隊尾，要留）：原本只有 [3]，新來了較小的 -1。雖然 -1 < 3，但它比較晚進框、活得比 3 久！先留著排後面當接班候補。當視窗往右滑一格、3 掉出框外時，剛才留下的 -1 立刻接班變成新視窗最大值 👑！

### Lab 3 · 雙端佇列兩扇門 ＋ 均攤 O(n)
- 一般佇列只能尾進頭出；因為我們要從尾巴踢人，所以用雙端佇列 deque：
  - 頭踢：pop_front() / Python popleft()
  - 尾踢：pop_back() / Python pop()
  - 尾進：push_back() / Python append()
- 均攤 O(n) 門票計數器：每個元素只有一張「進場券（綠點 1 次）」和一張「離場券（紅點 1 次）」。
  - 例：隊內有 [8, 6, 4, 2]，9 進場時 while 迴圈一口氣連踢 4 個。
  - 這一步雖然踢了 4 次，但這 4 個人用完離場券後以後再也不會出現！全部 n 個人加起來最多 2n 次操作 ➔ O(n)！

## 02 官方範例完整追蹤：nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3
預期輸出：[3, 3, 5, 5, 6, 7]（共 8 - 3 + 1 = 6 個視窗）
- i = 0, nums[0] = 1, 左界 = -2：dq 空 ➔ push 0 ➔ dq = [0:1]（未滿 k 格不記答案）
- i = 1, nums[1] = 3, 左界 = -1：隊尾 0:1 <= 3 ➔ pop_back(0) ➔ push 1 ➔ dq = [1:3]（未滿 k 格不記答案）
- i = 2, nums[2] = -1, 左界 = 0：隊尾 1:3 > -1 保留 ➔ push 2 ➔ dq = [1:3, 2:-1] ➔ 視窗 [0..2] 滿 k 格，記下 nums[1]=3 ➔ res = [3]
- i = 3, nums[3] = -3, 左界 = 1：隊頭 idx=1 >= 1 未過期；隊尾 2:-1 > -3 保留 ➔ push 3 ➔ dq = [1:3, 2:-1, 3:-3] ➔ 視窗 [1..3]，記下 nums[1]=3 ➔ res = [3, 3]
- i = 4, nums[4] = 5, 左界 = 2（高潮步驟）：
  1. 頭踢過期：隊頭 idx=1 < 2 ➔ pop_front(1)（3 出框）
  2. 尾踢廢物：隊尾 3:-3 <= 5 ➔ pop_back(3)；隊尾 2:-1 <= 5 ➔ pop_back(2)
  3. push 4 ➔ dq = [4:5] ➔ 視窗 [2..4]，記下 nums[4]=5 ➔ res = [3, 3, 5]
- i = 5, nums[5] = 3, 左界 = 3：隊頭 4 >= 3；隊尾 4:5 > 3 保留 ➔ push 5 ➔ dq = [4:5, 5:3] ➔ 視窗 [3..5]，記下 nums[4]=5 ➔ res = [3, 3, 5, 5]
- i = 6, nums[6] = 6, 左界 = 4：隊頭 4 >= 4；隊尾 5:3 <= 6 踢掉、4:5 <= 6 踢掉 ➔ push 6 ➔ dq = [6:6] ➔ 視窗 [4..6]，記下 nums[6]=6 ➔ res = [3, 3, 5, 5, 6]
- i = 7, nums[7] = 7, 左界 = 5：隊頭 6 >= 5；隊尾 6:6 <= 7 踢掉 ➔ push 7 ➔ dq = [7:7] ➔ 視窗 [5..7]，記下 nums[7]=7 ➔ res = [3, 3, 5, 5, 6, 7]

## 03 完整程式碼實作
### C++ (最佳 O(n) 單調雙端佇列)
```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        deque<int> dq; // 存放索引 index，對應的 nums[idx] 單調遞減
        vector<int> res;
        res.reserve(nums.size() - k + 1);

        for (int i = 0; i < (int)nums.size(); ++i) {
            // 1. 頭踢過期
            if (!dq.empty() && dq.front() < i - k + 1) {
                dq.pop_front();
            }
            // 2. 尾踢廢物
            while (!dq.empty() && nums[dq.back()] <= nums[i]) {
                dq.pop_back();
            }
            // 3. 新元素索引排入隊尾
            dq.push_back(i);
            // 4. 視窗湊滿 k 個起記錄隊頭最大值
            if (i >= k - 1) {
                res.push_back(nums[dq.front()]);
            }
        }
        return res;
    }
};
```
- Python (`collections.deque`) 對照：`popleft()`、`pop()`、`append(i)`、`nums[dq[0]]`。
- C++ 小細節：不用 `vector` 因為 `erase(begin())` 是 O(k)；過期檢查寫 `if` 即可（每輪只右滑 1 格最多過期 1 個）；`res.reserve(n - k + 1)` 可避免動態擴容。
- Max-Heap 備案 (O(n log n))：`priority_queue<pair<int, int>> pq;` 存 `{nums[i], i}`，取答案前用 `while (pq.top().second < i - k + 1) pq.pop();` 延遲刪除。

## 04 複雜度分析與高頻面試問答
複雜度對照：
- 單調雙端佇列 (Monotonic Deque)：Time O(n), Space O(k) — 本題標準最優解
- 分塊預處理 Prefix / Suffix Max：Time O(n), Space O(n)
- Max-Heap + 延遲刪除：Time O(n log n), Space O(n) — 面試忘記單調佇列時的最佳備案
- Multiset (`std::multiset`)：Time O(n log k), Space O(k)
- 每個視窗暴力重掃：Time O(nk), Space O(1) — 會 TLE 超時

面試 3 大必考追問 & 新手 3 大坑：
1. 為什麼有 `for` 包 `while` 還是 O(n)？均攤分析：n 個索引每個最多進列 1 次、出列 1 次，總計 <= 2n。
2. 為什麼 Deque 存索引不存值？要判斷隊頭是否滑出視窗左界 `i - k + 1`，遇到重複數字 `[5, 1, 5]` 才不會撞名。
3. 改求「滑動視窗最小值」怎麼改？只要把隊尾淘汰條件 `<=` 改成 `>=`（維護單調遞增佇列）。
4. 寫 `<=` vs `<` 的差別：推薦寫 `<=`，遇到一樣大時把舊位置踢掉、留較晚過期的新位置，佇列最短。
5. 新手 3 大坑：① Deque 存值不存位置 ② 沒寫 `!dq.empty()` 就取 `dq.back()` ③ 太早記答案（沒等 `i >= k - 1`）。
